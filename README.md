## ✨ Features

- **🔍 Auto-Detection** — Automatically detects PyTorch, TensorFlow, Scikit-Learn, and ONNX models
- **✅ Validation** — Validates model integrity, input/output shapes, and framework compatibility
- **🔄 ONNX Conversion** — Converts models to ONNX for optimized cross-platform inference
- **📊 Benchmarking** — Measures inference time, memory usage, and model size
- **⚡ API Generation** — Generates a production-ready FastAPI inference server
- **🐳 Docker Generation** — Creates Dockerfile and docker-compose for instant deployment
- **📦 ZIP Packaging** — Downloads everything (server code, Docker config, and the ONNX model) as a single ZIP file
- **🎨 Web Dashboard** — Dark-themed static single-page UI served directly by the backend

## 🏗️ Architecture

```
UniML/
├── backend/          # FastAPI REST API
│   ├── routers/      # API endpoints
│   ├── services/     # Business logic orchestration
│   ├── middleware/    # Error handling, security
│   └── utils/        # Logging, file utilities
├── web/              # React + Vite dashboard (built to web/dist, served by FastAPI)
│   ├── src/          # components, pages, contexts, hooks, lib
│   └── dist/         # production build output (generated by `npm run build`)
├── converter/        # Framework detection & ONNX conversion
│   └── handlers/     # Per-framework handlers (Strategy Pattern)
├── validator/        # Model validation engine
├── generator/        # Code generation (FastAPI, Docker, ZIP)
│   └── templates/    # Jinja2 templates
├── models/           # Pydantic schemas & enums
├── tests/            # Pytest test suite
├── deployment/       # UniML's own Docker config
├── docs/             # Documentation
├── uploads/          # Uploaded model files (gitignored)
├── generated/        # Generated output (gitignored)
└── logs/             # Application logs (gitignored)
```

## 🚀 Quick Start

### Prerequisites

- Python 3.11 or higher
- pip

### Installation

```bash
# Clone the repository
[git clone https://github.com/vivekghodekar001/UniML.git]
cd UniML

# Create virtual environment
python -m venv venv

# Activate (Windows)
venv\Scripts\activate

# Activate (macOS/Linux)
source venv/bin/activate

# Install dependencies
pip install -r requirements.txt
```

### Full ML Framework Support (PyTorch / TensorFlow)

scikit-learn and ONNX conversion work out of the box. PyTorch and TensorFlow
conversion need their (heavy) libraries in the **server's** environment — they
are intentionally kept out of `requirements.txt` so dev and tests stay light.

**Recommended — run in Docker (reliable, zero extra install):** the image bakes
in all conversion libraries, so conversion always works server-side regardless
of the host machine.

**Without Docker**, install the conversion stack into the same environment that
runs `uvicorn`, then start the server:

```bash
pip install -r requirements-convert.txt
```

On startup, UniML logs which converters are live (and warns about any missing
libraries), so you can confirm framework support at a glance.

### Running

The frontend is a React + Vite single-page app in `web/`. Build it once, then
the FastAPI backend serves both the REST API and the compiled dashboard from a
single process — no separate frontend server needed.

```bash
# 1. Build the dashboard (outputs to web/dist)
cd web
npm install
npm run build
cd ..

# 2. Start the backend (serves the API + the built dashboard)
uvicorn backend.main:app --reload --port 8000
```

Then open [http://localhost:8000](http://localhost:8000) in your browser.
Interactive API docs are available at
[http://localhost:8000/docs](http://localhost:8000/docs).

#### Frontend development

For hot-reload while working on the UI, run the Vite dev server. It proxies API
calls to the backend on port 8000, so run both together:

```bash
# Terminal 1 — backend
uvicorn backend.main:app --reload --port 8000

# Terminal 2 — Vite dev server (http://localhost:5173)
cd web && npm run dev
```

## 📡 API Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/health` | Health check |
| `GET` | `/info` | Platform info |
| `POST` | `/api/v1/upload` | Upload a model |
| `POST` | `/api/v1/detect` | Detect framework |
| `POST` | `/api/v1/validate` | Validate a model |
| `POST` | `/api/v1/convert` | Convert to ONNX |
| `POST` | `/api/v1/benchmark` | Benchmark a model |
| `POST` | `/api/v1/generate` | Generate deployment package |
| `GET` | `/api/v1/download/{id}` | Download generated ZIP |

## 🛡️ Security

- File extension whitelist validation
- Upload size limits (configurable, default 500MB)
- Path-traversal prevention on all client-supplied paths (requests are confined to the `uploads/` and `generated/` directories)
- Per-upload isolated directories
- Sanitized error responses (no server internals leaked to clients)

> ⚠️ **Note on untrusted models:** deserializing `.pkl`, `.joblib`, and PyTorch
> files can execute arbitrary code by design. Only process models you trust, and
> run UniML in an isolated sandbox when handling untrusted input. See
> [docs/architecture.md](docs/architecture.md#security-model) for details.
